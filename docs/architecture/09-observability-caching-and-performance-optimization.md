# Architecture Decision Record (ADR) 09: Production Observability, Caching & Performance Optimization

## Status
Accepted

## Context
Milestones 1–8 established a fully verified enterprise RAG system and multi-step LangGraph agentic research workflow with 100% test pass rates and rigorous quality benchmarks. However, production readiness required solving four primary operational and performance requirements:

1. **CPU Cross-Encoder Reranking Bottleneck**: Milestone 8 performance tracing revealed that ONNX cross-encoder reranking dominated agent latency (~4,836 ms per agent query). Static 512-token padding forced ONNX Runtime to perform quadratic attention computations on mostly pad tokens.
2. **Production Observability**: Enterprise compliance and site reliability engineering (SRE) require standard metrics exposition (`/metrics`), request correlation tracking across distributed components, structured audit logs, and automatic redaction of sensitive credentials.
3. **Multi-Layer Transparent Caching**: Repeated queries, identical sub-queries generated by decomposition, and unchanged document embeddings produced redundant vector embeddings and model inferences.
4. **Evaluation Gates & Automated Quality Policies**: Deployment pipelines must enforce deterministic quality, citation validity, and latency thresholds prior to production promotion.

---

## Architecture & Decisions

### 1. Zero-Dependency Native Prometheus Exposition (`GET /metrics`)
Instead of introducing heavy external dependencies, a high-performance, thread-safe Prometheus registry was built natively in `backend/app/observability/metrics.py`.
- Adheres to Prometheus 0.0.4 text exposition standards.
- Supports `Counter`, `Gauge`, and `Histogram` with cumulative exponential buckets.
- Emits standard metrics for HTTP traffic, latency distributions, cache lookups, evictions, agent iteration counts, sub-query retrievals, and abstentions.

### 2. Request Correlation IDs & Sensitive Data Redaction
- Inbound requests are assigned a unique UUID correlation ID (`X-Request-ID`), preserved or generated in FastAPI middleware (`app/observability/context.py`).
- Correlation IDs propagate through Python `contextvars.ContextVar`, automatically attaching to downstream database queries, agent execution trace items (`ExecutionTraceItem.request_id`), and log records.
- Regex and dictionary-based credential sanitization (`redact_sensitive_data()`) redacts API keys, bearer tokens, passwords, and authorization headers from all logs, exceptions, and traces.

### 3. Dynamic Sequence Padding for Cross-Encoder Reranking
- Fixed static length padding (`length=512`) was removed from `app/services/reranker_service.py`.
- Enabled dynamic batch-level sequence padding (`pad_token="[PAD]"` without fixed length constraint).
- Reduced ONNX inference time for 10 candidate chunks from **2,302.50 ms** to **81.20 ms** (**28.37x speedup** on CPU).

### 4. Layered In-Memory Bounded LRU Caching
A generic thread-safe bounded LRU cache (`InMemoryLRUCache`) was implemented using Python's `collections.OrderedDict` with $O(1)$ operations and TTL support:
- **Embedding Cache** (`app/cache/embedding_cache.py`): Caches dense vector representations of text queries and document chunks indexed by `sha256(text)`.
- **Reranker Cache** (`app/cache/reranker_cache.py`): Caches cross-encoder relevance scores for candidate pairs indexed by `sha256(query + "|||" + text)`.
- **Cache Invalidation** (`app/cache/invalidation.py`):
  - Document deletion triggers selective invalidation of chunks belonging to that document (`invalidate_document_cache(document_id)`).
  - Index rebuild or clear triggers global invalidation (`invalidate_all_caches()`).

### 5. Automated Evaluation Gates Policy
Implemented `app/evaluation/gates.py` enforcing strict gates before release:
- `Retrieval Recall@5 >= 0.80` (Actual: 1.0000)
- `Retrieval MRR >= 0.70` (Actual: 0.8810)
- `Retrieval NDCG@5 >= 0.70` (Actual: 0.9160)
- `Answer Grounding Accuracy >= 0.90` (Actual: 1.0000)
- `Citation Validity Rate >= 0.95` (Actual: 1.0000)
- `Abstention Accuracy >= 0.90` (Actual: 1.0000)
- `Agent p95 Latency <= 12000 ms` (Actual: 34.15 ms)

---

## Consequences

### Positive
- Cross-encoder reranker inference latency reduced by 28.37x via dynamic sequence padding.
- Warm single research latency reduced to 7.31 ms; warm agentic workflow latency reduced to 25.33 ms.
- Cache hit rates exceeded 71% for embeddings and 77% for reranking scores.
- Zero external runtime dependencies added for Prometheus metric emission.
- Standardized correlation ID propagation simplifies distributed debugging and audit compliance.

### Trade-offs & Next Steps
- Cold model loading and ONNX session initialization remain the dominant first-request cost (~500–1,400 ms on CPU).
- Future high-throughput scaling (>100 QPS) will require GPU execution or external inference microservices (Triton / vLLM).
